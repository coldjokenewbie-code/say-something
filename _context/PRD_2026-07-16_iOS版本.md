# PRD 2026-07-16:Say Something iOS 版本(公務機)

## 目標裝置(定案,來自使用者截圖)

- iPhone X、iOS 16.7.16、256GB、中華電信
- iPhone X 最終支援版本即 iOS 16.7.x,**永遠無法升 iOS 17** → 所有方案 deployment target 必須 ≤ iOS 16

## 需求

在公務機上達成 Android 版同等體驗:講話 → Gemini/Claude 轉錄+潤飾 → 取得文字使用。

## 技術事實查證(2026-07-16,均已實開連結驗證)

| # | 事實 | 對方案的影響 |
|---|---|---|
| 1 | iOS 鍵盤延伸(Keyboard Extension)**被系統禁止錄音**,即使開 Full Access 也回 `NOT allowed to start recording`;唯一變通是跳轉 container app 錄音再回鍵盤 | Android 版 IME 模式**無法照搬**;鍵盤方案體驗大打折扣 |
| 2 | Web Speech API(webkitSpeechRecognition)在 iOS「加到主畫面」的 standalone PWA 模式下**失效**(Safari 分頁內正常) | PWA 方案語音輸入需改走 MediaRecorder→Gemini 音檔路徑(專案已內建 `src/recorder.ts` 此備援) |
| 3 | 免費 Apple ID 側載:簽名 7 天過期、最多 3 app、需 Mac 重簽(通用常識,未驗證) | 原生 App 若無付費開發者帳號,不適合當每日工具 |

出處:
- [Apple Dev Forums — Recording audio in keyboard extension](https://developer.apple.com/forums/thread/742601)
- [Apple Dev Docs — Configuring open access for a custom keyboard](https://developer.apple.com/documentation/uikit/configuring-open-access-for-a-custom-keyboard)
- [Apple Dev Forums — webkitSpeechRecognition 於 PWA 失效](https://developer.apple.com/forums/thread/748048)、[WebKit bug 225298](https://bugs.webkit.org/show_bug.cgi?id=225298)

## 方案比較

### 方案 A:PWA iOS 適配(建議先行)

現有網頁版(GitHub Pages:`https://coldjokenewbie-code.github.io/say-something/`)針對 iOS 16 Safari 調整,公務機 Safari「加到主畫面」即用。

- 工作項:
  1. iOS 偵測與路徑切換:standalone 模式下停用 Web Speech、強制走 MediaRecorder(iOS 產出 `audio/mp4` AAC,Gemini 可收)
  2. 實機驗證 getUserMedia 在 iOS 16 standalone 可用性(已知風險:權限不持久、每次重問;若 standalone 不可用則退回「Safari 分頁使用」並在 UI 引導)
  3. iPhone X 適配:safe-area(瀏海/底部橫條)、`apple-touch-icon`、`apple-mobile-web-app-*` meta、manifest 補齊
  4. iOS Safari 剪貼簿:`navigator.clipboard.writeText` 需在 user gesture 內呼叫,串流完成後的自動複製要改成按鈕觸發
- 優點:零安裝門檻(公務機不需電腦、帳號、描述檔)、當天可交付、避開 MDM 限制
- 缺點:無系統鍵盤整合,結果需複製貼上;依賴 Safari
- 工時:小(現有碼 790 行,調整點集中)

### 方案 B:原生 iOS App(SwiftUI)

對應 Android app 架構:AVAudioRecorder 錄 AAC → Gemini `generateContent` 轉錄+潤飾 → 顯示+複製;API key 存 Keychain。min target iOS 16。

- 加值:鎖屏/控制中心快捷、Share Extension、App Intents 捷徑、體驗穩定
- 前提:**發佈方式必須先定案**(見待決 #2);免費帳號 7 天重簽不可行作為常用工具
- 工時:中(全新 Xcode 專案,約等於 Android 版規模)

### 方案 C:原生 App + 鍵盤延伸(Android IME 對等)——不建議

事實 #1 已封死鍵盤內錄音。變通(鍵盤按鈕→跳主 App 錄音→切回鍵盤插字)操作繁瑣,不如方案 B 的複製貼上。若日後仍要,作為方案 B 的延伸模組再評估。

## 建議路線

**階段一 = 方案 A**:立即可用、零風險驗證需求真偽。
**階段二 = 方案 B**:若 A 的複製貼上流程不滿足日常使用,且發佈方式(付費帳號或可接受重簽)確認後啟動。

- 減痛選項:AltStore(Mac 同 Wi-Fi 自動重簽)可後續再加;付費帳號 US$99/年 → Ad Hoc 一年有效,最接近 APK 體驗。
- 本機 Xcode 26.6 已就緒(`/Applications/Xcode.app`)。

## 方案 B 實作計畫

架構移植 Android 版(`android/` 的 Kotlin 實作為藍本),Gemini-only 起步(Claude 支援列選配):

| 模組 | 對應 Android | iOS 實作 |
|---|---|---|
| 錄音 | `MediaRecorder`(AAC) | `AVAudioSession`+`AVAudioRecorder` 錄 `.m4a`(AAC) |
| AI 呼叫 | `Gemini.kt` `generateContent`(inline audio base64) | `URLSession` 同款 REST,移植 `Prompts.kt` 七模式 |
| 設定 | `SharedPreferences` | API key 存 **Keychain**,模型/輸出語言存 `UserDefaults` |
| UI | IME 鍵盤列 | SwiftUI 單頁:大麥克風鈕+模式選擇+結果區+複製鈕;設定頁;歷史(近 30 筆,`UserDefaults`) |

- 專案位置:`ios/`(與 `android/` 平行),Xcode 專案 min deployment **iOS 16.0**,Personal Team 簽名。
- 部署:iPhone X 接 Mac → 啟用開發者模式(設定→隱私權與安全性)→ Xcode Run 安裝。
- 版控:`.swift`/`.pbxproj`/`.plist`/`.entitlements`/`.xcconfig` 比照 android 的 `.kt`/`.xml` 納入推送(見 `rules/git-sync-whitelist.md`)。

### 執行階段

1. 骨架:`ios/` Xcode 專案(SwiftUI、iOS 16、簽名設定)+ `.gitignore`(DerivedData/build)
2. 核心:Recorder、GeminiClient、Prompts 移植、Keychain 設定存取
3. UI:主畫面/設定頁/歷史,safe-area 適配 iPhone X
4. 實機部署與驗收(見下)
5. `ios/README.md`:安裝步驟+7 天重簽 SOP

## 階段 6:Session 式鍵盤延伸(2026-07-16 使用者追加,Wispr Flow 架構)

需求:所有輸入框都能直接輸入潤飾內容(同 Android IME 體驗)。鍵盤延伸不能錄音(事實 #1),採業界先例 [Wispr Flow](https://docs.wisprflow.ai/articles/7453988911-set-up-the-flow-keyboard-on-iphone) 的 session 架構:

- **錄音者=主 App 背景**(UIBackgroundModes: audio;前景啟動 audio session 後背景保活——AVAudioEngine 持續跑、未擷取時丟棄樣本)。
- **鍵盤=遙控器+插字**:🎤/停止/七模式鈕;透過 Darwin notification(跨進程信號)+App Group 共享容器(資料)指揮主 App;結果 `textDocumentProxy.insertText` 直接進輸入框。
- **Session 啟動**:鍵盤「啟動」鈕以 responder-chain 手法開主 App(URL scheme `saysomething://session`),App 啟動錄音保活後以私有 API `suspend` 自動彈回(側載無審查限制;失敗降級=使用者手動切回)。
- **App Group**:`group.com.saysomething.app`(免費 Personal Team 可用性未驗證;不可用時降級=named UIPasteboard 傳資料,Darwin notification 傳信號)。
- 鍵盤需 Full Access(網路/共享容器);延伸記憶體上限約 60-70MB,不引重框架。
- 體驗差異(已向使用者揭示並接受):每 session 首次要跳轉啟動一次;session 被 iOS 回收後需重啟動。

## 驗收條件(方案 B)

- iPhone X iOS 16.7 實機:開 App → 按麥克風講中文(夾英文)→ 停止 → 30 秒內顯示潤飾文字 → 一鍵複製到其他 App 貼上成功
- 七模式可切換,設定(key/模型/語言)重啟後保留
- 無麥克風權限/無網路/API 錯誤時有明確中文錯誤訊息,不閃退
- 瀏海與底部橫條不遮擋操作元件
